# 中转站折扣采集与展示

## 存储与取值顺序

每个「站点 / 分组 / 原始型号 / 计价方式」报价独立保存：

| 列 | 含义 |
|---|---|
| `discount_ratio` | 相对基准的价格比例；0.72=7.2折，不是优惠72% |
| `discount_source` | `station_reported` 站方直接提供 / `station_formula` 复现站方公开展示公式 / `calculated` 本站计算 |
| `discount_basis` | 站内模型基准、官方输入价、公开参考输入价，禁止混淆 |
| `discount_details_json` | 公式、参数、对比来源、采集时间、分组、规则来源URL与哈希等证据 |

优先站方明确给出的值，其次已核实的站方展示公式，否则按可比参考输入价计算。适配器必须先把站方字段规范化为比例，不能猜测一个未知字段究竟是“折数”“优惠百分比”还是“价格比例”。通用解析入口为 `resolveTransitDiscount`。

无折扣来源时：仅对相同型号和单位（USD / M Token）且明确基础输入价格的报价计算；站内额度必须具备实付兑换依据和人民币/USD换算依据。阶梯或峰时条件无法对齐、基准为零、缺少充值换算、无价格来源等情况不计算，不把缺失值补成0折或1折。社区参考价只标“公开参考”，不冒充厂商官方核价。

原始报价观察记录包含折扣详情；公开JSON快照包含对应列。写侧计算，前台只读既有内存/JSON缓存，不在刷新时请求数据库或外站。

## Packy 专用适配

已核对当前公开页面：
- 公开接口 `/api/pricing` 提供模型/分组覆盖倍率，`/api/status` 的 `price` 提供充值单价。
- 官方充值文档明确1元人民币对应1美元站内额度：<https://docs.packyapi.ai/docs/register/>。
- 首页实际加载的主JS包包含公开折扣展示规则；当前海外基准换算为6.9，指定国产模型前缀基准为1。
- 基础折扣比例=`price × (model_group_ratio[group][model] ?? group_ratio[group]) ÷ 基准换算`；不是把分组倍率再乘一次覆盖倍率。

采集器每次读取首页引用的同源主JS包，限时/限量下载并存档，使用窄规则识别当前公式、换算数和前缀列表；不执行下载的JS，也不永久写死6.9。页面包结构/公式不能识别时产生告警并安排15分钟补扫；有完整公开参考价和换算依据时才启用本站测算。

每条报价保存来源URL、规则哈希、充值单价、有效分组倍率和参考换算值。折扣不包含峰时、阶梯和个人充值活动；值≥1仍入库但不伪装成折扣标签。缺少倍率的模型保留空值。

报价成功但折扣依据失败时，不把旧折扣无条件套到新的报价上；当前折扣置空或切换到有依据的测算结果，旧证据留在观察历史中。必要报价采集失败则继续保留上次完整快照。

## 标签

- 首页模型名右侧沿用 `ToneChip`，16px高、9px字、10px `BadgePercent` 图标；原25px行高和卡片外框保持不变。仅局部调整模型表列宽，为标签留位。
- 标签折扣必须取**当前输入/输出展示报价所在的同一个分组**，不能单独挑最低折扣或拿区间端点冒充。
- 绿色表示站方参考，蓝色表示本站测算。鼠标/键盘可打开Base UI自定义浮层，简要显示来源性质、分组、对比基准及不含条件；不是浏览器默认title。
- 不显示≥10折、不确定/无效值；极小正值显示“<0.1折”，真实零价显示“免费”。

## 运行

正常统一调度：`pnpm worker`，沿用站点6小时采集及失败补扫。

`pnpm collect:transit -- --pricing-only` 仅更新报价/元信息/折扣并重建快照，不请求模型性能接口，也不删除已有性能小时记录。
本轮改动前的代码和SQLite在线备份：`work/transit-discount-before/`（备份后缀`.bak`，不参与TypeScript编译）。
