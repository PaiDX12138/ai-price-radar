## 自动更新

现有Worker每分钟发现并分派本站任务，SQLite持久化到期/租约/补采状态：

| 任务 | 周期 |
| --- | --- |
| 全量报价、阶梯、媒体矩阵、支付参考配置 | 6小时 |
| 有近期请求的型号性能 | 1小时 |
| 无近期请求的型号 | 6小时再检查；有流量后自动进入小时队列 |
| Logo核对 | 1日；强制采集可立即核对 |

性能主体持久化排队；单轮预算180秒，超时留待补采；连续3次失败停止扩散，401/403/429停后续请求。请求串行，间隔至少350ms。源只提供小时均值/率，十五日主值采用现有等权逻辑，不冒充按请求数加权SLA。

**需要现有Worker保持常驻才能持续更新。** 本轮没有擅自增加长期后台进程或第二套cron。已有Worker会自动发现新增配置；部署后沿用原进程管理方式启动/重启即可。

## 执行命令

在项目根目录：

```bash
pnpm transit:migrate
pnpm collect:transit --station=crazyrouter
pnpm transit:status
```

仅刷新价格、不重拉所有监测：

```bash
pnpm collect:transit --station=crazyrouter --pricing-only
```

仅处理到期任务：

```bash
pnpm collect:transit --station=crazyrouter --due
```

常驻进程仍是项目原有 `pnpm worker`。不要重复增加cron/多个网站进程。网站 `/api/transit` 可确认实际进程读到了哪些站点、模型数，不暴露原始数据和数据库路径。

## 保存规范

- 写侧 `data/transit.sqlite`，前台读 `data/transit/latest.json`；不要求重建或清空数据库。
- 新增目录版本、支付配置版本、性能主体队列、独立24小时摘要四张表。小时原点复用带站点/型号/分组身份的事实表，重复拉取不会增加重复时间点。
- 价格、折扣、分组率、缓存时长、表达式、媒体单位和矩阵条件分别保存，不在入库时裁剪小数。两位小数限制只在倍率/紧凑价格展示层应用。
- 24小时摘要不复制成小时数据；状态页总TPM不写成模型输出t/s。
- 原始响应gzip归档；接受的报价/支付版本保留hash引用原文；无引用传输副本7日，小时历史与滚动摘要35日。
- 更新失败保留last-good，日志保留具体阶段；价格失败不清除历史，性能失败不抹掉有效报价。
