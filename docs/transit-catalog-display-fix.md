# 首页模型目录与价格显示修复

日期：2026-10-29（北京时间）。

## 已观察到的证据

- 用户线上截图首页四行均为国内平台，不能据此证明数据库只有这四个平台。
- 本次匿名读取 PackyAPI `/api/pricing` 返回77个型号，包含 `claude-opus-5-5`、`gpt-6-astra`、`gemini-4-argon` 等。原站当前不是只有国内模型。
- 本地旧快照包含 Claude 42条、GPT 23条、Gemini 8条等分组报价。服务器实际快照、运行目录、环境变量和采集日志本次没有取得，不能声称线上根因已最终证实。

## 代码修改

1. 明确的原始模型平台身份优先于社区目录的 provider 标签，防止第三方转售目录把模型归到其他平台。社区元数据不再覆盖采集器明确返回的文本模态，避免文本型号因为附加元数据被排除出默认目录。
2. 社区目录导入时只接受可识别型号所属的原厂平台记录，避免跨厂商覆盖同名型号信息。
3. PackyAPI 新增已知四大平台的完整性门槛。若响应缺 Claude/GPT/Gemini/DeepSeek 的全部有效报价，报 `incomplete_pricing_families` 并保留旧数据，而不是把完整目录覆盖为残缺目录。该名单是 Packy 当前运营范围的配置，不适用于其他站点；站方确认永久调整时需同步配置。
4. 首页文本、图片报价及详情分组摘要最多两位小数，去掉无意义尾零，原始存储不舍入；极小正值显示 `<0.01`，不是免费。模型悬浮详情保留原精度。
5. 增加只读 `pnpm transit:status`，输出快照绝对路径、生成时间、各站分组数、模型数、按平台报价数及最近采集状态，不打印秘钥或原始数据。

## 服务器定位与恢复

在网站/Worker共同使用的项目根目录执行：

```bash
pnpm transit:status
pnpm collect:transit -- --station=packyapi --pricing-only
pnpm transit:status
```

如果快照本身缺平台，查看采集结果，只有完整成功采集才会补齐；如果快照已有 Claude/GPT/Gemini 而网页仍缺，应核对网站进程的 cwd、`TRANSIT_SNAPSHOT_PATH`、是否构建/重启到新版本及浏览器当前筛选条件，而不是继续改写报价数据。

本轮没有取得服务器端运行证据，没有运行测试、类型检查、构建或浏览器验收。
