# 中转站点存储与缓存（基础版）

## 目标

- SQLite 负责写入、索引、历史审计。
- Worker 负责采集和生成快照。
- Next 前台只读 `data/transit/latest.json`，不在请求期间打开 SQLite，也不请求外站。

## 文件

```text
data/transit.sqlite          # 写侧真相源，由 Worker/CLI 使用
data/transit/latest.json     # 读侧快照，原子替换
data/transit/raw/            # 已保存原始响应，按内容哈希去重
```

初始化：

```bash
pnpm transit:migrate
```

## SQLite 表

- `transit_stations`：站点档案、发布状态、收录时间、最近采集状态。
- `transit_groups`：站点分组、充值系数、模型倍率、号池和披露信息。
- `transit_offers`：当前模型报价；按站点/分组/原始模型/价格类型唯一。
- `transit_offer_observations`：每次成功采集的不可变报价观测。
- `transit_collection_runs`：采集运行审计和错误信息。
- `transit_source_snapshots`：原始 JSON/HTML 响应、响应头、源站时间、哈希和解析状态。
- `transit_collect_schedule`：持久化下次采集时间、连续失败次数和租约；重启不丢调度。

站点、分组和报价表同时保留扩展字段：Logo、文档/监测链接、采集器配置、分组说明、协议覆盖、厂商、计费模式、分层价格、图片/视频计费、base/effective 价格配置及原始 JSON。新增字段采用可空列和 JSON 字段，不会因为某站点暂时没有某项信息而丢失整条记录。

已建立的查询索引覆盖：站点状态、站点 host、采集器类型、源指纹、站点分组、模型族/模态、厂商/标准模型、报价更新时间、采集运行时间、原始快照哈希。

## PackyAPI 当前接口映射

PackyAPI 的公开 `/api/pricing` 可以写入：

- `data[].model_name` → `transit_offers.raw_model`
- `enable_groups` + `group_ratio` → `transit_groups`
- `model_ratio` / `completion_ratio` / `cache_ratio` → 报价倍率字段
- `supported_endpoint_types` 与 `model_group_endpoints` → 协议 JSON 字段
- `vendor_id`、`quota_type`、`tiers`、`image_billing` → 报价扩展字段
- 整个响应 → `transit_source_snapshots.payload_text`

该接口暂时不能单独证明真实可用率、实际请求量或模型身份；这些不在当前阶段入库为“本站实测”。

## 读缓存

`src/lib/transit/snapshot.ts` 使用两层判断：

1. 进程内存缓存，默认 300 秒，可用 `TRANSIT_CACHE_TTL_SECONDS` 调整（60–3600 秒）。
2. 30 秒内直接复用内存，不访问文件系统；之后检查 mtime，变化时加载新快照，不必等 TTL 到期。

读取失败时继续返回内存中的上一份有效快照；冷启动也可回退到 `latest.json.last-good`。页面不查询数据库或调用外站。

## 更新节奏

已接入 `pnpm worker`，PackyAPI、RightAPI 与 ZetaAPI 各自使用独立采集器及站点配置：

线上缺站点或平台不全时，先运行 `pnpm transit:status`，同时查看candidate失败记录；浏览器可读取no-store的 `/api/transit`，用快照指纹与CLI对照。2026-10-30故障和恢复流程见 `docs/transit-server-collection-incident.md`。中转HTTP支持同源及配置白名单重定向，支持显式固定出口，不再把底层连接原因隐藏成单独的fetch failed。

- 所有已启用站点统一 6 小时更新，不按活跃度分档；`TRANSIT_COLLECT_INTERVAL_HOURS` 支持 6 / 12 / 24。
- 上一项指报价。RightAPI 的公开可用率独立每小时回扫24h，保留真实小时后积累本站15日历史；PackyAPI 沿用每6小时回扫360h。Worker按站点分别启动子进程，避免某站缓慢阻塞其他站。
- ZetaAPI 每5分钟抓取公开心跳，原始点去重入库后按小时聚合，积累15日历史；24小时和360小时摘要单独存储，不能代替小时序列。模型、基础设施、公开报价容器三种作用域分开，未公开耗时不使用ping代替。规范见 `docs/zetaapi-integration-plan.md`。
- Worker 独立每分钟检查到期任务，不等待店铺采集完成；使用 SQLite 租约防止多进程重复采集，进程退出后过期租约可以回收。
- 请求有超时和响应大小上限；失败在 15 / 30 / 60 / 120 / 240 / 360 分钟后补采。403 / 429 至少等待一小时，并遵守 `Retry-After`。
- 必要报价响应无效时保留上次成功数据与更新时间；Logo、首页或元信息失败不覆盖已保存内容，并在 15 分钟后补采。
- 完整成功响应中消失的分组 / 报价标记下架，保留历史。异常空响应不清空数据。
- 官方 Logo 验证后保存本地；原始接口、首页、状态响应保留，未公开的渠道、充值换算、可用率、缓存命中率不推测。
- 价格按各站点币种和计费语义保存：Packy/Right的站内额度不能与Zeta的USD报价混同。折后有效价不重复乘倍率；模型计费倍率不等于充值比例。阶梯、动态峰时和图片 / 视频规格规则保留原始字段；未确认的实付人民币和规格单价不展示为确定报价。

采集完成后先写 SQLite，再原子替换 `latest.json`。前台只看到完整旧快照或完整新快照，不会读到半写文件。

```bash
pnpm collect:transit             # 手工采集（仍遵守正在持有的租约）
pnpm collect:transit -- --due     # 仅处理到期站点，重试导出快照
```

## 界面保持

折扣采集、存储字段、站方/本站测算区分及首页紧凑标签见 `docs/transit-discounts.md`。参考折扣不改变“分组倍率不是官方折扣”的既有含义。

复用原有站点卡片、分组卡片、监测柱图、模型检测和真伪比对组件，不重排板块，不改变原有尺寸和配色。监测区域依用户确认改为“15日可用率”；时间行改为“首Token：xxxms / 15日均 xxxms”。未接入的真伪检测保留原板块空态。详情筛选 Tab 仅显示该站真实报价支持的平台 / 图片 / 视频类别。

## 15日性能历史（2026-10-28 接入）

模型检测卡片现已接入同一批小时记录，详情见 `docs/transit-model-performance.md`。新增按原始型号导出的 15 日聚合、有效小时、响应耗时与 TPS；模型结果不使用站点或分组均值兜底。

- `/api/perf-metrics?model=...&hours=360` 是唯一小时数据源。对定价清单的每个模型串行请求，间隔100ms，单请求超时20秒；性能阶段总预算120秒。连续3次失败停止本轮，403/429立即停止并遵守冷却 / Retry-After。
- `/api/perf-metrics/summary?hours=360` 原始响应也存档，但其小时耗时有大量零值，不混入详细数据计算。
- 新表 `transit_performance_observations`：唯一键为站点、原始模型、分组、UTC小时、查询窗口。保存成功率、平均耗时、首Token、TPS、数据有效性、源URL、源schema和采集时间。重扫同小时更新原行，不重复累加。
- 每次仍回扫完整15日，以补齐失败或迟到的小时；原始历史留在SQLite，公开快照仅输出当前15日聚合结果。复用原有统一6小时调度，不因每小时存储而每小时向外站请求。常驻Worker需部署启动 `pnpm worker` 才会执行调度。
- 有效性：100%且所有耗时/TPS均为0，按“未确认有样本”处理；0%等失败记录即使耗时为0仍保留。0耗时不当成0ms响应。缺桶不补成功，不复制相邻小时。
- 整站：每小时先将同模型不同组等权聚合，再对模型等权；单组：仅使用该组的模型。再按有数据小时等权计算15日均值。**这是明确标注的模型等权可用率指数，不是请求量加权SLA**，因为源站不公开总请求量/成功请求数。与官方顶层模型概览的均值可能不同。
- 可用率、首Token、平均耗时使用同一份小时记录、同一滚动360小时网格。首Token取最新有数据小时的平均TTFT，右侧15日均为响应平均耗时，不将二者混为一谈；当前小时可能未结束，tooltip给出实际桶及采集时间。
- 页面保持60根细条：每根固定6小时，共15日；按时间从旧到新排列。颜色表示该段成功率（≥99%绿、95%–99%黄、<95%红），高度表示该段平均耗时（全站统一0–120s对数刻度，超过120s封顶）；无覆盖灰色。tooltip给出区间和有效小时数，缺数据不会压缩时间轴。
- Worker在写侧预聚合60根细条和均值，前台只读内存/JSON快照，不扫描SQLite或请求外站。采集失败保留已采小时，快照损坏仍有last-good兜底。部分模型失败会安排补扫，不清空其他模型。
- 作用域校验：公开聚合结果携带 `scope.stationId / groupKey`。首页只取整站作用域，分组卡片显式按原始 `group_key` 取值；站点或分组不匹配时显示空态，禁止以整站结果兜底。测试同时验证组件选数合同，防止只改组名却复用整站百分比、细条与耗时。开发热更新若保留了旧页面数据，完整刷新后再做端到端核对。

### 细条高度与悬浮窗

- 采用固定对数映射，不再按各卡片最大耗时缩放：1s约30%高、10s约59%、30s约77%、60s约88%，≥120s为100%。异常长耗时不再压平同卡其他细条，不同卡片同耗时同高度。无数据采用短灰条；颜色仍只表示可用率。
- 每条使用Base UI自定义Tooltip（同图共用一个浮层），显示时间段、可用率、首Token、平均耗时、有效小时。单位仅ms/s。缺数据直接显示暂无数据，不使用浏览器默认title。Portal防止被卡片裁剪，支持键盘左右键、Home/End与Esc。
- 卡片整体Link蒙层不能覆盖细条的交互区域；仅提升细条层级，不改变卡片尺寸、网格、配色及其他板块。
- SSR与客户端使用同一renderedAt计算收录/更新时间，避免跨分钟hydration失败导致首次悬浮交互失效。
