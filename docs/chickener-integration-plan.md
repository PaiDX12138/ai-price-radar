# 鸡哥AI（chickener.top）接入与采集方案

研究日期：2026-11-02，北京时间约19:00–19:04完成在线取证，随后离线核算。现已按本方案完成独立采集接入与本机正式入库，运行记录见[采集说明](chickener-collection.md)。下文库存是研究时点证据，不写死为未来接口数量；线上服务器仍需要部署新代码并导入公开数据包。

## 1. 结论与范围

该站可以以匿名公共接口为主接入，不需要浏览器自动化或API调用密钥来取得当前报价及公开模型性能。使用独立 `chickener_v1`，复用项目的传输、租约、小时事实、快照和现有UI，不套用Packy/RunAPI整站采集器。

本轮仅串行、限时GET官网、官网实际引用的前端资源、文档和已发现的接口；没有注册、登录、购买、创建令牌或调用付费模型。当前本机出口为direct，**不能据此保证阿里云服务器出口也正常**。网页搜索工具无法读取该站时，以本机直接HTTP响应取证；第三方价格网站不是入库来源。

## 3. 价格解析：最重要的实现点

### 3.1 不能只看 `group_ratio` / `usable_group`

两字段本次都只有default。按它们过滤会漏掉8个有公开报价的分组。应以每个型号的 `enable_groups` 为关系真相，倍率优先取明确返回的 `all_group_ratio`，并核对其数值有效性。

| 分组 | 倍率 | 当前型号数 |
|---|---:|---:|
| default（体验用户） | 1 | 15 |
| 【Claude】仅限claude code调用 | 1.2 | 2 |
| 【Deepseek】稳定分组 | 0.25 | 2 |
| 【GPT】生图分组 | 0.25 | 2 |
| 【GPT】稳定分组 | 0.25 | 8 |
| 【GPT】高缓存分组 | 0.35 | 6 |
| 【Gemini】稳定分组 | 0.27 | 1 |
| 【Grok】稳定分组 | 0.25 | 3 |
| 【Kimi】稳定分组 | 1 | 3 |

“公开报价存在”不代表所有匿名/新账户都能选择该组。保留账户可选性与公开报价范围两个属性；不把Claude Code限定描述删除。福利组0.135虽在字典中，但没有当前型号成员，不生成虚构的第10组在售卡片。

### 3.2 表达式优先，不能退回错误占位倍率

分流规则：

1. `billing_mode=tiered_expr` 且有 `billing_expr`：只按解析成功的表达式定价，`model_ratio` 等原字段留作原文，不拿来覆盖表达式。
2. 普通Token：百万Token输入基础价为 `2 × model_ratio`；输出、缓存读写依相应倍率；最后乘真实组倍率。
3. `quota_type=1`：`model_price × 组倍率`，本次单位只能确认“次”，不能擅自写成“一张”或“每秒”。
4. 未识别表达式保留原文及错误，标价为空；不伪装成零元，不用错误的通用倍率兜底。省略的缓存项为未知，显式零价与缺字段分开。

当前表达式使用：`tier`、`len`上下文阈值、`p/c/cr/cc/cc1h`收费项、`param("service_tier")`、priority/fast、逻辑或/与及`weekday/hour("Asia/Shanghai")`。

现有解析器离线兼容实测：RunAPI只接受其中2条DeepSeek表达式，另外13条失败；CrazyRouter当前实现不能完整接受这15条。因此单独实现有长度/深度限制的白名单AST解释器；复用十进制运算，不执行站方JS，不用`eval`或`Function`。不能通过字符串删掉priority、长上下文或峰时条件来“解析成功”。

本轮研究解释器已离线解析全部15条、核算42个成员报价，并测试上下文边界、priority/fast和工作日峰谷边界。仅在`work/`用于验证，不冒充生产接入代码。

### 3.3 可复现价格样例

以下为**站内名义标价单位**，文本单位为百万Token。默认条件为短上下文、普通服务等级，DeepSeek为谷时；并非已核实的实付人民币。

| 型号 / 组 | 输入 | 输出 | 缓存读 | 基础缓存写 / 1小时写 |
|---|---:|---:|---:|---:|
| gpt-6.1-sol / GPT稳定 | 0.5 | 2.5 | 0.025 | 0.625 / 未给出 |
| claude-opus-5-5 / Claude组 | 4.8 | 24 | 0.24 | 6 / 9.6 |
| deepseek-v4.1-flash / Deepseek稳定（谷时） | 0.25 | 1 | 0.0125 | 未给出 |
| gemini-3.8-flash / Gemini稳定 | 0.2025 | 1.0125 | 0.02025 | 0.2025 / 未给出 |

两个图片型号均为基础0.4/次，default实际0.4/次，GPT生图组0.1/次。首页图片Tab和详情价格沿用现有媒体价格组件，不展示输入/输出倍率伪装成按次价格。

`cc`保存为基础缓存写收费，`cc1h`保存为1小时写收费；原始响应没有为所有型号明确基础缓存TTL，不能仅因项目内部旧字段名带5m，就对所有GPT或Gemini宣称它一定是5分钟缓存。

特别注意：

- gpt-6.1-sol原 `model_ratio=37.5`，直接算会得到稳定组输入18.75，而表达式是0.5，相差37.5倍。
- Claude Opus原倍率字段推导组内输入1.2，表达式却是4.8；不能选看起来较低的一套价格。
- GPT上下文条件是`len <= 272000`，Grok是`len <= 200000`。超过阈值或选择priority/fast，输入、输出与缓存收费要按对应分支整体变化。
- DeepSeek仅北京时间周一至周五09:00–12:00、14:00–18:00翻倍，周末不翻倍。写入规则与时区，Worker在边界本地重算当前投影，不靠6小时后重新抓取才能切换峰谷。

### 3.4 币种、充值与折扣

公开状态是`quota_display_type=CNY`、`price=1`、`usd_exchange_rate=1`、`quota_per_unit=500000`。这些能够证明界面配置，**不能单独证明真实支付1元获得1美元余额**。当前文档只让用户以钱包/购买页为准；没有取得不含条件的支付报价证据。

因此存储 `displayCurrency=CNY`、原始兑换参数和 `currencyKind=station_credit`（明确是站内计价），充值换算继续为空/未验证；不能使用`stripe_unit_price=8`反推全站人民币汇率。

公开`redemption_bonus_tiers`为`10:0, 50:0, 100:5, 300:10`，可作为兑换加赠原始配置保存；面额单位、支付渠道和适用条件未经钱包验证，不转换成所有模型的无条件额外折扣。邀请奖励也不是本站用户首充福利，不添加赞助标记。

没有发现独立的官方模型折扣字段。后续仅当原始型号、官方基准、缓存/上下文/服务等级和币种口径均匹配时计算同口径参考折扣；输入、输出分别存，混合比例不强行合成一个数字。组倍率0.25不自动等于相对厂商官方的2.5折。没有同口径依据时不显示折扣标签，但保留实际站内报价。

## 4. 可用率、时间与历史作用域

### 4.1 实际能取得的内容

明细包含`model_name`、`series_schema`、`groups[].group`及每小时`ts / avg_ttft_ms / avg_latency_ms / success_rate / avg_tps`，可满足首页、详情分组及模型检测现有指标。`series_schema`保留原值，不把当前哈希写死为永久协议。

本轮21型号明细共2,519点；66点为0%成功率，必须保留为失败事实。本轮没有发现“100%且所有耗时均0”的占位点，生产解析仍应覆盖这个情况。TTFT为0时不解释为真实0ms，也不拿总耗时填TTFT。

接口不提供每小时总请求数/成功请求数，不能反推出请求量加权SLA、缓存命中率、Token总量或模型真伪。TPS是源站性能指标，不用于图片“张/秒”推算。

### 4.2 三种不能混合的数据

1. **当前报价成员**：42个模型—组关系，只有41个有小时记录。缺的是`kimi-k3.1-pro-highspeed / 【Kimi】稳定分组`，不拿default组数值复制过去。
2. **历史或非当前成员**：Gemini福利组、gpt-5.6-luna高缓存组、两个图片型号GPT稳定组，共85小时点。不删除源历史，但不能展示成当前报价关系的监测；首轮可保存完整响应及关系审计，只投影当前成员事实。
3. **只有概览、没有当前报价的型号**：`kimi-k3-256k`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`、`gpt-5.5`。概览25型号不等于当前在售25型号，不生成报价或卡片。

### 4.3 15日计算口径

- 查`hours=360`并校验时间戳按UTC整点、去重、不超未来容差，当前小时标partial。
- 缺少记录不等于采集没运行，也不等于失败；可能无请求、源历史未留存或型号/组尚未启用，公开数据不足以确定原因。
- 固定360小时网格、60根6小时细条，不压缩空档、不补0/100、不复制邻近小时。
- 每个当前模型/分组仅使用自己的源小时。站点每小时先对同型号的有效当前组等权，再对当前型号等权，最后按有数据小时等权计算15日指数；无请求数权重时明确为系统模型等权统计，不称请求量SLA。
- 分组已有直接型号—组小时数据，优先使用这些，不以总站概览兜底。没有对应组观测时保持空值，不能把同型号另一真实组当本组实测。
- 模型检测对所选型号的真实记录聚合；仅源站确实只给型号级且无组数据时，才采用项目既有“系统汇总”逻辑。
- 站方概览本轮`success_rate=99.37`，但包含25型号且未给请求数及精确聚合规则，单独保存为源摘要；不会强行把同一百分比同时放到整站、各组和所有型号。

## 5. 落库结构

沿用 SQLite → 原子快照 → 前台只读，不向浏览器直出外站请求，也不在页面加载时触发采集。

| 存储位置 | 内容 |
|---|---|
| `transit_stations` | 独立id `chickener`、官网/文档/Logo、系统、能力与币种配置，站点赞助字段默认不设置 |
| `transit_groups` | 9个当前有成员报价组、原始key、显示名、倍率、Claude Code限制；字典中无成员的组保留版本元信息，不构造有效报价 |
| `transit_offers` | 42条当前关系：计费模式、基础价/组内有效价、基础缓存写/1h写、协议声明及冲突、完整tiers、表达式和来源版本 |
| `transit_offer_observations` | 报价成功观测，不用当前价格覆盖历史观测 |
| `transit_offer_charge_items` | 输入、输出、缓存等分项；缺项null，显式0价仍为0 |
| `transit_performance_observations` | 当前已验证成员小时，唯一键沿用站点/原始型号/组/UTC小时/窗口360；TTFT、总耗时、成功率、TPS及validity；后续完整小时覆盖partial而非反向 |
| `transit_source_snapshots` + raw归档 | JSON/HTML/Logo的来源、HTTP状态、hash、采集时间、版本与解析结果；所有未投影的历史关系也保留源原文 |
| `transit_collect_schedule` / `transit_performance_schedule` | 价格和性能独立任务、租约、下次执行、失败退避 |
| `transit_collection_runs` / worker心跳 | 每阶段审计、完成/失败/部分完成、库存、耗时、最近自动调度及错误原因 |

建议新增三张站点专用表（均为正式实现时迁移，本次未建）：

- `transit_chickener_catalog_versions`：主键站点+内容hash；保存pricing_version、完整目录/成员/表达式、库存及解析器版本、first/last_seen。
- `transit_chickener_metadata_versions`：主键站点+内容hash；保存白名单币种/注册/兑换配置、完整性与来源。概览可以按`kind+window_hours`记录独立摘要版本，绝不覆盖小时事实。
- `transit_chickener_metric_subjects`：主键站点+原始型号；保存next_attempt、last_success、fail_count、last_error、是否当前活跃，支持预算耗尽后继续未采型号。

保留小时事实35日，页面使用滚动15日；价格/表达式版本长期审计，raw按hash压缩去重并独立设置清理策略。清理不得删除当前版本引用或运行中临时文件。公开基线导出需将新增公开版本表加入白名单，但**队列、心跳、运行错误、登录资料不进入Git数据包**。

## 6. 自动采集与失败处理

| 任务 | 建议频率 | 行为 |
|---|---|---|
| 价格/元信息 | 默认6小时 | status+pricing，校验后事务写入；当前共21型号，不能把首屏若干项当全量 |
| 型号性能 | 独立每小时 | 当前21型号逐一查360小时；串行间隔200–300ms，单请求20s，总预算120s；持久化游标避免总是只采前几项 |
| 性能概览 | 与小时任务一起 | 1个额外GET，独立源摘要，失败不抹掉已成功明细 |
| Logo/文档 | 每日或版本变化 | 内容/尺寸/格式校验；只有变更时写正式本地资产；失败保留旧正确Logo |
| 峰谷投影 | 精确边界/每分钟本地检查 | 不访问外站；按已保存的Asia/Shanghai规则重算，不更改原始采价时间 |

既有 `pnpm worker` 每分钟检查、默认两站并发即可；一个站点只有一个actor，价格与性能分别认领租约。定价失败仍可用已验证last-good目录继续性能任务；单型号失败不清空其它型号。401/403/429立即结束该类本轮请求，遵守Retry-After；普通连续三次失败停止，15/30/60分钟等退避后继续。
