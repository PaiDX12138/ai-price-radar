# Cubence 独立采集接入方案

研究日期：2026-10-30（北京时间）。下文保留研究依据与增强链设计；**公开基础报价链现已完成正式接入和首次入库**，当前实施范围、调度、验证结果与登录数据限制见 [采集运行说明](cubence-collection.md)。全程未操作浏览器，未调用收费推理接口。

## 结论

可以先完整接入 **公开基础报价目录**，采用独立 `cubence_v1`，复用现有 SQLite、Worker、快照和卡片。不能直接套用 PackyAPI 的接口或倍率计算。

关键边界：公开目录明确是 `USD / base / global`；**不是各分组的最终调用价**。模型广场、分组和站内状态接口的无登录请求均返回401。应将公开基础报价与需要登录的实际分组报价分为两条数据链，不能用基础价冒充分组实价，也不能把没有拿到监测数据写成100%可用。

| 本次公开目录 | 实测数量 |
| --- | --- |
| 不重复原始型号 | 73 |
| 厂商 | 12 |
| Token计费型号 | 70，其中包含部分生图型号，不能全部当文本模型 |
| 固定图片计费型号 | 3 |
| 带Token阶梯的型号 | 13，共26个档位 |
| 已验证公开的实际分组报价 | 0，不代表站点没有分组 |
| 已取得的可用率、耗时、吞吐监测记录 | 0，不代表站点没有监测 |

模型页与价格表页的结构化目录逐字段一致；已用11项离线校验检查重复型号、字段、阶梯边界和特殊价格。

**采集方式选择：** 当前无需浏览器DOM采集。公开模型页虽没有验证到独立目录JSON接口，但完整目录已经随HTML返回，服务端直接GET后解码其JSON即可。公开设置走JSON；文档与Logo作为补充；登录接口不能静默降级为公共基础价。

推理线路 `api-lb.cubence.ai / api.cubence.ai / api.cubence.com` 是官方文档列出的调用入口，不是已经验证的定价或监测备源。本轮未请求这些推理服务。

## 2. 目录解析与完整性

### 公开模型字段

保留顶层 `currency / price_basis / region_scope`，逐型号保存：

- `model_name`：原始型号身份，不改名、不删除日期或渠道后缀。
- `vendor_id`、`vendor.id/name/slug`：厂商归属；前端平台展示归一化另存。
- `billing_mode`、`request_billing_strategy`、`request_price`。
- `input_price / output_price / cache_read_price / cache_write_price`。
- `pricing_tiers[]`：每个档位的上下界与四类Token价格。
- `updated_at`：源报价更新时间，与我们本次 `observed_at` 分开。

公开目录没有返回实际分组成员、分组倍率、监测数字，也没有完整的逐型号协议/输入输出模态字段；这些不能根据厂商品牌就宣称已取得。按现有受限规则识别明确的图片型号，未知项保留原值，后续用官方型号详情或接口补充。

### 无执行解析器

1. 限定主站HTTPS来源、响应大小和重定向。
2. 提取 `self.__next_f.push([1,"…"])` 的字符串JSON；只使用 `JSON.parse`，不执行远端脚本。
3. 合并分段，解码合法JSON记录，定位唯一的 `catalog.models`。
4. 对数字类型、币种、原始型号唯一性、厂商引用、阶梯完整性做强校验；多个相冲突目录视为失败，不随意取第一个。
5. 校验失败保留last-good并记录解析版本与错误，不切到抓取页面可见的前几条卡片。

现有73不是永久固定值。初始可设置最低20个型号、较上一有效目录减少超过20%或既有Claude/GPT/Gemini/DeepSeek整族消失时隔离本轮结果。留待人工确认真实下架后再更新基线，不能让服务器地域差异或页面改版清空目录。

## 3. 价格计算的专用规则

### 基础价与Token阶梯

官方明确：输入、输出、缓存读取、缓存写入的单位均为 **USD/百万Token**。匹配用的提示词Token数为三项之和：输入＋缓存读取＋缓存写入；上下界均包含。命中某档后，**整条请求使用该档费率替代基础费率**，不是分段累加，也不是再乘一次基础价。

| 需要特别验证 | 本轮证据 | 处理 |
| --- | --- | --- |
| GLM零基础字段 | `glm-5 / glm-5.1` 的基础输入输出为0，但有非零有效阶梯 | 不能显示免费；默认小请求报价取覆盖0Token的首档，并明确档位条件 |
| 基础价不等于首档 | `gpt-5.6-sol` 基础输入5，首档4；`gpt-5.6-terra` 基础2.5，首档2 | 基础值、首档报价分存，不混用 |
| 不同门槛 | Haiku为100000，GLM为32000，Grok/Qwen为200000，GPT本轮为272000 | 每型号读取原始上下界，不统一写死门槛 |
| 不规则缓存价 | `gpt-6-luna` 第二档缓存写入2.6 | 保存源值，不套通用的1.25倍公式 |
| 零与缺失 | 多个型号缓存写字段为0 | 保存0；不使用 `value || default` 补价，也不凭0推断该模型支持免费缓存写入 |
| 无关策略字段 | Token型号也出现 `request_billing_strategy=dynamic` | 先按 `billing_mode` 分支，不把70个Token型号都识别为动态图片 |

主卡片有阶梯时可沿用现有阶梯详情组件，数字展示使用首档并由共享提示说明其条件；不能取任意最低价暗示全请求通用，也不能把基础价和阶梯价横向拼成不存在的报价。

### 图片与视频

- 当前3个固定图片型号：`gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`，公开基础价均为 **$1/返回图片**。不是整个多图请求总共1美元。
- Gemini部分生图型号仍按Token计费，应保持输入/图片输出Token口径，不强转成每张价格。
- 文档定义了动态图片的USD/1,048,576像素口径，以及请求面积上限、返回尺寸不可读时回退请求尺寸的规则。但当前3个按图片记录均为 `fixed`，本轮没有实际 `per_request + dynamic` 型号，不能将文档能力伪装为已采集动态价。
- 本轮目录没有明确的视频型号报价。目录缺少视频能力不能靠套用其他站点的单价来补齐。

### 折扣与充值

- 本轮公开型号数据没有明确的折扣字段。可在精确匹配本地官方参考型号、同币种、同单位、同档位后计算**基础价对比**；它不等于账户现金实付折扣。无匹配参考不显示折扣，不以别名近似匹配。
- 最终分组报价取得后，再计算该分组适用档位的报价对比，并保留参考来源、价格基准、时点和计算方式。源直接披露的折扣也要记录它对应基础价还是分组实价。
- 公开设置本轮返回 `alipay_rmb_to_balance_rate=1`、`stripe_rmb_to_usd_rate=6.6628`、最低充值30、最高5000、充值开启、订阅关闭。这些是不同支付配置，**不能直接推出“¥1=$1”**。
- 当前前端存在与实时设置不同的初始化默认值（例如0.6和订阅开启）。正式采集以成功返回的设置JSON为准，不抄前端默认常量；请求失败则标旧值/未知，不用默认值覆盖。
- 充值奖励、返佣比例不作为所有型号的统一折扣。账户额度、支付币种和Token报价单位按照官方文档分开保存。

## 4. 分组报价：可选登录数据链

当前前端代码能证明以下字段的用途，但**401意味着尚未验证真实业务响应中的当前值和覆盖范围**：

- `/api/model-plaza` 预期返回 `success`、`data.models`；客户端还兼容旧厂商数组结构。
- 型号存在 `group_ids`、`groups[]`，分组包含 `id/name/base_multiplier/schedule_enabled/effective_multiplier_range/timeline[]`。
- `timeline[]` 包含 `at/multiplier`；前端选择当前时间对应的倍率，关闭排程时用基础倍率。不能将当前排程倍率再与基础倍率重复相乘。
- `billing_timezone / display_timezone` 要保留。前端缺失时回退亚洲上海/美国洛杉矶，这只是客户端默认值，不是当前响应已证明的时区。
- `share-groups/available` 用于补充真正可用的分组与说明；成员必须按原始ID关联，不能把厂商分类当分组。

正式实施分两步：

1. **公开模式默认开启**：完整保存基础目录；使用现有 `synthetic_public_catalog` 语义表示“公开基础报价”，不展示虚构的真实渠道倍率或分组数量。
2. **登录增强模式独立开关**：有合法有效的专用会话来源后，先验证真实JSON和账户覆盖，再采实际分组。凭据只保存在部署环境，不进入快照、日志、原始响应归档或Git。401即停止该链并标会话失效，不反复重试，不将公开基础数据冒充增强结果。

某账户可见的分组只代表该账户范围，保存 `access_scope` 与采集身份的不可逆标识；不将其声明为全站全部分组。旧的实际报价可以保留并标过期，但不静默用基础价覆盖。

## 5. 监测与十五日保存

### 目前已知与未知

站内当前前端按60秒刷新状态。状态归一化代码接受：

```text
updated_at / anchor / resolution_minutes
models[].model_name / current_status / availability / blocks[]
blocks[].t / s（up、warn、down、none）
分组详情：model_name / overall / groups[].share_group_id
可选状态块：ttft / r[] / srl / ttftl
```

客户端把 `ttft` 按毫秒格式化，提示为TTFT P95；`r`可包含 `error_rate / slow_ttft / slow_generation`，`srl/ttftl`用于异常原因的阈值提示。因此：

- **P95不能当平均首Token，也不能平均各块P95当作15日平均耗时。**
- `warn`可能仅代表响应慢，不等于请求失败；`down`的判定也需要结合源规则。
- `srl`在客户端用于错误率阈值提示，不是本次请求成功率或样本数。
- `availability` 的统计窗口、是否排除无流量、是否计入慢响应均未取得实际响应/规则确认。不能把它直接标成15日请求成功率。
- 尚无经过响应验证的吞吐 `t/s`、平均耗时、请求总数、缓存命中率。价格里的缓存读写字段不能用来计算缓存命中率。
- 外部健康面板本轮403，没有取得其接口，不复用RunAPI状态站路径猜测数据。

### 获取真实监测响应后的保存方式

1. 原始块以 `station + access_scope + model + group_scope + resolution + source_timestamp` 唯一，重复拉取幂等更新、保留修订hash；模型、分组、站点三个作用域不得互相套用。
2. 统一UTC落库、北京时间展示，保存源窗口、源更新时间与采集时间。跨采样周期或上下文变化的块不直接拼接。
3. **滚动15日**使用真实时间区间 `[now-15d, now)`，落到360个小时格。按时间相交长度聚合原始状态，未公开/未覆盖时间保留缺失，不补正常、不算0%。
4. 若未来能取得成功数/请求数，则按真实计数汇总请求可用率；若只有状态块，只能另存、明确展示“正常时段占比”，不伪装请求成功率。源汇总率按原窗口独立保存，不平均重叠窗口来造历史。
5. 仅在指标语义确认后启用15日数字；源不足15日则持续积累，显示实际覆盖，不倒填采集前的数据。没有可计算字段时维持现有缺失状态，不制造新装饰卡片。
6. 细条沿用每6小时一条、15日60条的现有组件；颜色来自该时间桶已确认的指标，数据不足为灰。没有有效平均耗时就统一高度，不使用随机高度。悬浮窗只留时间、指标、覆盖、来源。
7. 有实际分组状态优先用分组源；缺分组但有可信模型指标且成员关系明确时，才用现有模型汇总逻辑按成员/时间去重计算。没有成员/指标，或只有P95而无均值时，不生成虚假的综合耗时；汇总不能称渠道实测。

**公共模式当前不启用空转监测轮询**，只记录能力缺失原因。避免每分钟重复401，并与“站点故障”区分。

## 6. 入库与读取规范

### 复用现有业务表

- `transit_stations`：名称、首页/文档/状态入口、Logo、`collectorKind=cubence_v1`、来源能力和公开/账户范围。
- `transit_groups`：公开目录的合成报价范围；增强链才存真实分组及原始ID、时区与倍率版本。
- `transit_offers`：原始型号与厂商、计费类型、USD币种、图片单位、`tiers_json / base_price_json / effective_price_json / source_model_version`。
- **公开基础价的 `effective_price_json` 留空**；默认适用阶梯是基础报价的一种展示条件，不等于实际分组实价。倍率未知留null，不补1。
- `transit_offer_observations`：成功采集的报价历史与源hash；存储不截成两位小数，只在展示层格式化。
- `transit_source_snapshots / transit_collection_runs`：来源URL、HTTP结果、内容hash、解析版本、计数和错误；失败不能清空成功数据。

### 少量Cubence专用表（实施时迁移）

| 建议表 | 存什么 | 唯一身份 |
| --- | --- | --- |
| `transit_cubence_catalog_versions` | 不可变完整目录、型号分布、基础价格版本 | station + access_scope + version_hash |
| `transit_cubence_metadata_observations` | 白名单公开支付配置与来源语义 | station + version_hash |
| `transit_cubence_group_price_versions` | 增强链真实成员、基础倍率、时间线、时区；与公开基价分开 | station + access_scope + group_id + version_hash |
| `transit_cubence_status_blocks` | 真正取得的模型/分组状态原块及原因、TTFT P95 | station + access_scope + model + group_scope + resolution + source_timestamp |
| `transit_cubence_metric_summaries` | 源披露汇总率及明确的统计窗口/指标语义 | station + scope + metric_kind + window_start/end + source_updated_at |
| `transit_cubence_monitor_schedule` | 仅启用增强监测时使用的游标、租约、会话失效状态和下次时间 | station + access_scope + task_key |

阶段A只建/使用目录与公开配置表；增强分组/状态表随该功能实际启用再迁移，不为未知数据抢建伪指标列。监测保存原始状态而不是硬塞入其他站点的请求计数表；TTFT P95独立存储。

### 归档、事务与快照

- 公开HTML/JSON按内容hash压缩归档；引用保留的价格版本不能被清理成悬空证据。无引用的运行原文可短期保留，报价变更历史长期保存，监测原点至少保留35日。
- 登录响应只保存白名单业务字段并计算规范化业务hash，不归档响应头、Cookie、账户资料或会话内容。
- 每一数据链先完整拉取/校验，再事务写入；定价失败不损坏监测，设置失败不否定已验证目录。记录分阶段状态，不能用“部分成功”掩盖主目录失败。
- Worker成功后原子生成 `data/transit/latest.json`；前台不连外站、不读SQLite。发布基础模式时明确价格口径；增强链的最后成功时间独立于基础模式。

## 7. 定时更新与稳定性

| 任务 | 建议周期 | 失败行为 |
| --- | --- | --- |
| 公开目录/阶梯 | 6小时，首轮立即 | 保留last-good；缩减隔离；退避重试 |
| 公开设置 | 6小时，与目录同轮但分状态 | 保留旧设置并标旧；不使用前端默认值补齐 |
| Logo/文档规则检查 | 1日或资源变化时 | 本地已验证Logo继续使用，不在用户请求期间加载外站 |
| 登录分组报价（可选） | 验证成功后6小时；时间线到边界立即重算快照 | 401停该链；时段倍率不等6小时才变更 |
| 登录模型状态（可选） | 首次验证后按返回resolution/保留窗口设定，初始可5分钟 | 按源时间去重；401停、429按Retry-After；不伪造间隔缺口 |
| 分组状态详情（可选） | 真实成员分批补采，低频轮换 | 不每轮全型号扇出；预算内串行、游标可恢复 |

接入现有Worker常驻调度与持久化租约，不在Next页面中加定时器，也不新增操作系统cron与Worker重复采。请求沿用20秒超时、8MiB上限、受限同源跳转；串行并设请求间隔，总任务预算到期保存游标。相同401不重试；网络/5xx采用15分钟→1小时→6小时退避并加抖动。

服务器首次上线先核实同一来源返回的型号分布、四大模型族和配置；若网络环境产生缩减目录，保留上次完整版本并记录错误，不能靠重置数据库解决。专用出口仅通过已有采集器环境配置，日志不打印其凭据。
