## 数据与版本

继续使用 `data/transit.sqlite` 作为写侧、`data/transit/latest.json` 作为前台读侧。正式迁移是增量建表，无需清库：

- `transit_cubence_catalog_versions`：规范化完整目录、分布、解析版本及原始响应hash；同内容只更新最后观测时间，真正价格变化创建新版本。
- `transit_cubence_metadata_observations`：白名单支付配置版本、首次/最后观测时间和原始响应hash。
- 共用 `transit_offers / transit_offer_observations`：当前报价、每轮观测、原始型号/厂商、价格、全部阶梯及更新时间。
- 公开报价明确 `currencyKind=usd_base`，只写 `base_price_json`；不写分组有效价、不伪造倍率1×。
- 读侧只为本采集器导出其经过白名单构造的基础价格对象；不导出原站脚本、完整rawOffer、采集配置和运行原始数据。

原始HTML/JSON/SVG按内容hash存入 `data/transit/raw/cubence/*.txt.gz`。SQLite只保存hash和路径，不重复存大段HTML。保留每个已接受目录/配置版本引用的原文；未被版本引用的原始副本保留7日。清理仅作用于本采集器归档路径，并同步清除失效运行路径，不删除其他站点或目录文件。

## 调度及失败语义

无需新建cron；现有Worker自动发现 `config/transit/cubence.json`，每分钟分派 `--due --station=cubence`，只有SQLite中到期的6小时任务真正联网。

- 首次启用立即到期；`--force`不能抢占其他进程的有效租约；5分钟租约过期可恢复，单轮预算100秒。
- 主目录校验成功后才事务替换当前报价、追加版本、完成调度。型号骤减超过20%、必需模型族消失、字段不合法或未知计费方式均保留last-good。
- 支付配置/Logo为可选阶段：失败不会丢弃有效目录，保留上一成功值，记录警告并15分钟后补采。
- HTTP403/429停止本轮后续请求，遵守Retry-After；不会轮换未知接口或反复请求登录接口。
- 前台请求只读快照，不访问外站。监测能力在诊断中显示 `login_required / pollingEnabled=false`，不能将其理解为0%可用。

本轮检查时本机未发现项目常驻Worker；没有为本次接入另起一个长期后台进程。**持续自动更新需要开发/服务器已有Worker保持常驻。** 已完成正式首次采集和实际 `--due` 跳过验证，不需要用户刷新页面来触发采集。

## 运行与排障

在项目根目录执行：

```bash
pnpm transit:migrate
pnpm collect:transit --station=cubence
pnpm transit:status
```

常驻采集沿用现有服务的启动方式：

```bash
pnpm worker
```

网站进程仍使用既有 `pnpm start` 或部署进程管理器；不要为了新增站点另开第二个生产网站进程。诊断真实网站进程读到的站点及数量，可GET网站自身 `/api/transit`，该接口不暴露数据库路径、凭据或原始响应。

只验证到期任务、不强制重复采集：

```bash
pnpm collect:transit --station=cubence --due
```

服务器若得到缩减目录，应先看具体采集错误、模型族分布和采集出口；不能清数据库或把本机样本长期当线上真数据。
